# CornerMan 拳角 · MVP 产品需求文档

> 本 PRD 面向第一个可验证版本。短期内的唯一用户是**训练者本人**：训练后上传视频、AI 自动分析、用户自我补充与校正，沉淀为可追踪的训练档案。教练协作、场馆版本、社交分享均不在 MVP 范围。

## 0. 关键指标

| 项目 | 取值 |
| --- | --- |
| 唯一用户 | 训练者本人（拳击爱好者，每周 2-4 次训练） |
| 训练后完成记录目标 | 5 分钟内 |
| 建议 MVP 周期 | 6 周 |
| 第一版技术评分模型 | 5 个维度 |
| 核心闭环 | 上传 → AI 分析 → 自我补充 → 归档 → 趋势 |

## 1. 背景与问题

拳击训练的进步高度依赖复盘，但普通爱好者的视频、感受、教训通常散落在相册、聊天软件和记事本里。训练当下感觉强烈，几天后很难复现具体问题，也无法判断某个技术缺陷是否真的改善。

MVP 要解决的不是"AI 一眼看出你拳击水平"，而是让训练者**一个人**就能把每次训练沉淀为：

- 一份结构化记录；
- 一个 AI 起草、自己补全和修正的复盘报告；
- 一组可追踪的关键片段和趋势。

### 核心假设

- 训练者愿意在训练后花 3-5 分钟上传视频和补充感受，只要系统能明显减少自己整理与回看的成本。
- AI 给出的起草内容（摘要、问题、建议）即使不完美，只要可编辑、可标记片段证据，用户就愿意基于它做"二次创作"。
- 单人闭环跑通后，再叠加教练协作与社交，是更稳的演进路径。

## 2. 用户与场景

MVP 阶段只有一种用户：**训练者本人**。

| 维度 | 描述 |
| --- | --- |
| 画像 | 拳击爱好者，每周 2-4 次训练（含私教课、自训、约练实战） |
| 设备 | 训练现场用手机拍视频；复盘以 PC 为主，移动端 H5 为辅 |
| 现有习惯 | 拍视频存相册、写微信/备忘录碎片记录、隔几天就翻不到 |
| 期待 | 训练后能"快速倒带 + 自动提炼 + 我补一句"，长期看到自己在变好 |

典型场景：

- **场景 A：私教课后 30 分钟内**——回家路上用手机上传视频，补一句"今天练 jab + 后撤，膝盖有点紧"，等 AI 跑出初版报告。
- **场景 B：当晚或第二天，PC 复盘**——在大屏上看视频，逐条修订 AI 给出的优点/问题，给关键片段贴标签、写一句话备注。
- **场景 C：每周末**——查看本周训练量、重复问题、评分趋势，决定下周自我训练重点。

## 3. 产品目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 训练后 5 分钟内完成记录 | 用户上传视频 + 补充感受，并看到 AI 初版报告 |
| G2 | 让复盘从"凭感觉"变成"有证据" | 报告中的每条结论可绑定片段或用户记录 |
| G3 | 让用户愿意修订而不是默读 | 报告中用户编辑/补充率 ≥ 60% |
| G4 | 形成持续成长档案 | 按周/月展示训练量、重复问题、评分变化 |

## 4. 非目标

| 编号 | 暂不做 | 原因 |
| --- | --- | --- |
| NG1 | 教练协作（批注、改分、布置作业） | 控制范围，先跑通单人闭环 |
| NG2 | 场馆版、多人账号 | 商业化方向后置 |
| NG3 | 报告社交分享、社区 | MVP 不做内容平台 |
| NG4 | 裁判级实战判分 | 第一版不承诺自动判断胜负 |
| NG5 | 完整拳种高精度识别 | 可辅助识别片段，但不作为核心承诺 |
| NG6 | 直播实时指导 | 先做训练后异步复盘 |
| NG7 | 硬件绑定（心率、拳速传感器） | 后续扩展 |

## 5. MVP 主流程

```
创建训练 → 上传视频 → AI 初步分析 → 用户自我补充与校正 → 归档并进入趋势
```

1. **创建训练**：选择类型（私教课 / 自训 / 实战约练）、时长、地点；填写本次重点和主观感受（文字输入）。
2. **上传视频**：单或多视频，移动端可直接相册/相机录制，PC 可拖拽批量；后台生成缩略图、转码、抽帧。
3. **AI 初步分析**：自动生成训练摘要、3 个优点、3 个问题、5 维评分（含置信度）、下次训练建议；每条结论挂上"证据片段"。
4. **用户自我补充与校正**：
   - 修改/删除/新增 AI 给出的结论；
   - 收藏关键片段、打问题标签、写一句话备注；
   - 修正评分（拉滑块），系统记录"AI 原始 vs 用户修订"差异；
   - 可补一段文字总结，附加到报告。
5. **归档**：报告进入个人训练档案，自动并入趋势。

| --- | --- | --- | --- |

| US2 | 作为训练者，我想快速补一句训练感受（文字） | 记录当下主观感觉 | Must |
| US3 | 作为训练者，我想看到 AI 自动生成的优点、问题、评分和下次建议 | 不用自己从头写 | Must |
| US4 | 作为训练者，我想逐条修改/删除/新增 AI 的结论 | 让报告变成我自己的复盘 | Must |
| US5 | 作为训练者，我想给关键片段打标签、写备注 | 复盘时能定位证据 | Must |

## 7. 功能需求

| 模块 | 需求范围 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 训练记录 | 创建训练、选择类型、填写时长/地点/感受（文字） | Must | 用户能在 1 分钟内完成训练元数据录入 |
| 视频上传 | 移动端相册/拍摄、PC 拖拽批量、断点续传 | Must | 单个 10 分钟视频可后台稳定上传 |
| 视频处理 | 转码、缩略图、抽帧、片段切分、关键片段推荐 | Must | 10 分钟视频在 5 分钟内出初步报告 |
| AI 复盘报告 | 摘要、3 优点、3 问题、5 维评分、下次建议、证据片段 | Must | 每条结论可关联至少一个片段或用户记录 |
| 用户修订 | 增删改报告条目、修正评分、补充总结 | Must | 修订与 AI 原始版并存，可回看差异 |
| 片段库 | 收藏、标签、备注，按标签检索 | Must | 用户能按问题标签反查所有相关片段 |
| 问题追踪 | 标记问题为"已改进 / 仍存在 / 新增"，跨训练贯穿 | Should | 趋势页能展示同一问题的多次出现 |
| 趋势看板 | 周/月训练量、评分趋势、重复问题、训练完成率 | Must | 至少支持周 / 月两个视角 |
| 报告只读链接 | 生成脱敏只读链接 | Should | 用户能一键拿到可分享链接（不做 PDF/图片） |

## 8. AI 与自我补充的协作模型

报告分两层，明确"AI 起草、用户定稿"：

| 层 | 来源 | 可编辑 | 用于训练数据 |
| --- | --- | --- | --- |
| AI 原始版 (`draft`) | 模型自动生成 | 否（只读快照） | 是 |
| 用户修订版 (`final`) | 用户在 draft 基础上增删改 | 是 | 是（带 diff） |

交互原则：

- 每条 AI 结论旁有「采纳 / 修改 / 删除 / 新增」操作；
- 用户修改后，旁边小字保留 AI 原文，方便回看；
- 用户新增的条目标记为「我补充」，在趋势分析时单独统计；
- 评分修正记录 `(ai_score, user_score, delta)`，用于后续模型调优。

### 单次训练报告结构

- **训练摘要**：本次训练类型、强度、重点动作、整体状态。
- **做得好的地方**：最多 3 条，必须绑定片段或用户记录。
- **主要问题**：最多 3 条，按影响训练效果排序。
- **评分**：5 个维度评分 + 解释 + 置信度，用户可拉滑块修正。
- **下次训练**：2-4 个具体练习建议，用户可勾选"下次重点关注"。
- **我的补充**：用户自由记录（文字输入）。

## 9. 评分模型

| 维度 | 指标 | 权重 | MVP 实现方式 |
| --- | --- | --- | --- |
| 基础姿态 | 站架稳定、重心、手位、下巴保护 | 20% | AI 初筛 + 用户校正 |
| 出拳质量 | 发力链、伸展、回位、非出拳手保护 | 25% | 关键片段评分 |
| 脚步移动 | 进退、侧移、出拳后位置、交叉步风险 | 20% | 半自动标签 |
| 防守习惯 | 出拳后回防、头部离线、被压迫时反应 | 20% | 片段证据 + 用户校正 |
| 节奏体能 | 回合内输出波动、疲劳后动作变形 | 15% | 视频节奏 + 主观疲劳 |

评分必须可解释：每个维度返回 `score / confidence / evidenceSegmentIds / rationale`。用户可对任意维度做修正，但 AI 原始分会被保留。

## 10. 数据对象

| 对象 | 字段说明 |
| --- | --- |
| User | 训练者基础信息、训练经验、站架、目标 |
| TrainingSession | 训练日期、类型、时长、地点、主观感受、本次重点 |
| VideoAsset | 原始视频、转码版本、缩略图、时长、处理状态 |
| VideoSegment | 起止时间、片段类型、用户标签、问题码、AI 置信度、用户备注 |
| AnalysisReport | AI 摘要、评分、建议、风险提示、版本（draft / final） |
| ReportRevision | 用户对报告每一条目的增删改记录 |
| ProblemThread | 跨训练贯穿的"同一类问题"，含出现次数、最近状态、改进证据 |
| TrainingMetric | 周/月趋势、问题频次、评分变化、训练完成率 |

## 11. 指标与埋点

验证 MVP 是否成立的关键指标：

- **激活**：新用户完成首个训练上传 + 看到报告的比例。
- **修订率**：报告中用户编辑/新增/修正评分的条目占比（目标 ≥ 60%）。
- **片段沉淀**：人均收藏片段数 / 每次训练。
- **留存**：7 日、30 日内再次上传训练的比例。
- **趋势使用**：每周打开趋势页的用户占比。
- **AI 质量**：被用户删除或大幅修改的 AI 条目比例与原因标签。

## 12. 里程碑（6 周）

| 时间 | 阶段 | 交付物 |
| --- | --- | --- |
| 第 1-2 周 | 骨架 | 训练记录、视频上传、视频转码、报告页静态布局 |
| 第 3-4 周 | AI 闭环 | LLM 起草报告、5 维评分、证据片段、用户逐条修订 |
| 第 5 周 | 片段与追踪 | 片段库、问题标签、ProblemThread 跨训练串联 |
| 第 6 周 | 趋势与上线 | 周/月趋势、报告只读链接、埋点与灰度上线 |

## 13. 风险与上线准入

- **关键风险**：视频角度、遮挡、光线和手套高速运动会影响 AI 判断。MVP 必须展示置信度，让用户可以一键修订或删除 AI 结论；任何被包装成"绝对判断"的设计都要砍掉。
- **次要风险**：用户不愿意修订报告 → 把修订入口做到极轻（一键采纳、滑块改分、卡片右上角即删）。
- **上线准入标准**：用户在不依赖任何人工运营的前提下能完成"创建训练 → 上传 → 看到 AI 报告 → 修订并保存 → 看到趋势"全流程，且 PC 与移动端均可用。
